**Event:** Hacktoberfest Hack Day Pune x ACES (MLH)
**Prize category:** Best Open-Source AI Project (DigitalOcean)
**Stack:** React (Vite) frontend · FastAPI backend · Open-weight LLM on DigitalOcean Serverless Inference · Hosted on DigitalOcean App Platform
**Team:** 2 people · **Goal:** a fully working, deployed demo

---

## 1. Problem

Many students learn best by **teaching** a concept out loud (the Feynman technique). Others revise 4–5 concepts a day but can't recap them properly by evening.

Both groups hit the same wall:
- There is nobody to explain the topic to.
- Even if someone listens, they usually can't tell what was **correct**, what was **wrong**, and what was **missed**.

## 2. Solution

**Recap Buddy** is a web app where a student:
1. Picks a topic and optionally uploads their notes (PDF / DOCX / TXT).
2. Explains the topic **out loud**; the browser transcribes it live.
3. Gets a review from an **open-weight AI model** running on DigitalOcean, sorted into four buckets:
   - ✅ Correct and well explained
   - ⚠️ Partially correct (with a fix)
   - ❌ Wrong (with the correct version)
   - 🕳️ Missed concepts (and why they matter)
4. At the end of the day (or whenever they want), generates a **Learning Diary**: a one-page summary of every topic recapped that day, downloadable as Markdown.

**Rules the AI must follow:**
- Never judge grammar, accent, filler words or transcription errors — **only concepts**.
- If notes are uploaded, treat them as the source of truth.
- If no notes, use the model's own knowledge at standard textbook level.
- Never invent mistakes the student didn't make.

## 3. Goals and non-goals

- Voice explanation → live transcript → AI review in 4 buckets + score

## 5. End-to-end user flow

1. Student opens the app URL.
2. **Session setup:** types a topic name (e.g. "Photosynthesis"). Optionally uploads notes → backend extracts text → UI shows "Notes loaded: N pages".
3. **Teach:** clicks **Start Teaching** → browser asks for mic permission → live transcript appears and keeps updating. Clicks **Stop**. The transcript stays editable (also the fallback if the mic isn't available — they can just type).
4. **Review:** clicks **Get Review** → loading state → review card shows score, summary, the 4 buckets and a "Revise next" tip.
5. The review is saved automatically to **Today's Sessions** (browser storage).
6. Student clicks **New Topic** and repeats steps 2–5.
7. **Diary:** clicks **Generate Today's Diary** → backend writes a Markdown diary from all of today's reviews → rendered on screen → **Download .md** button.
8. Student can open any past session from the sidebar, delete it, or clear the day.

- Review response in under ~20 seconds for a 2-minute explanation.
- Works on Chrome/Edge desktop (voice) and any modern browser (typing).
- API key never reaches the browser and is never committed to Git.

## 8. Architecture

```
Browser (React + Vite)
  ├─ Web Speech API  → live transcript
  ├─ localStorage    → today's sessions
  └─ fetch("/api/...") (same domain)
            │
DigitalOcean App Platform (one app, two components)
  ├─ Static Site  "frontend"  → route  /
  └─ Web Service  "backend"   → route  /api   (FastAPI + Uvicorn)
            │  OpenAI-compatible HTTPS
DigitalOcean Serverless Inference  (https://inference.do-ai.run/v1)
  ├─ gemma-4-31B-it        (primary, open-weight)
  └─ openai-gpt-oss-120b   (fallback, open-weight)
```

Because frontend and backend share one domain, the frontend calls relative paths like `/api/review` — **no CORS setup and no API URL env var needed in production**. In local development, Vite's dev-server proxy forwards `/api` to FastAPI.

## 11. Backend API specification

Base path: `/api`. All responses are JSON.

### `GET /api/health`
- **Purpose:** deployment check + show model in footer.
- **Response:** `status: "ok"`, `model` (primary model ID), `fallback_model`.

### `POST /api/extract`
- **Request:** `multipart/form-data` with field `file` (PDF, DOCX or TXT, ≤ 10 MB).
- **Response:** `filename`, `pages` (PDF only, else null), `chars`, `text` (truncated to ~80,000 chars), `truncated` (true/false).
- **Errors:**
  - 400 — unsupported file type
  - 413 — file too large
  - 422 — no extractable text (e.g. scanned PDF) → message "This file has no readable text. Try a text-based PDF or paste notes."

### `POST /api/review`
- **Request JSON:**
  - `topic` (string, required)
  - `transcript` (string, required, ≥ 15 words)
  - `reference` (string, optional — the extracted notes text)
- **Response JSON (review object):**
  - `topic` (string)
  - `score` (integer 0–100)
  - `summary` (string, 1–2 encouraging sentences)
  - `correct` — list of `{concept, note}`
  - `partial` — list of `{concept, what_was_said, fix}`
  - `wrong` — list of `{concept, what_was_said, correct_version}`
  - `missed` — list of `{concept, why_it_matters}`
  - `next_step` (string)
  - `grounded` (true if reference notes were used)
  - `model` (model ID that answered)
- **Errors:**
  - 400 — transcript too short
  - 502 — both models failed → message "AI is busy, please retry"

### `POST /api/report`
- **Request JSON:** `date` (YYYY-MM-DD), `reviews` (list of review objects from today).
- **Response JSON:** `markdown` (diary text), `model`.
- **Errors:** 400 — empty reviews list; 502 — model failure.

### Backend behaviour rules
- Read `MODEL_ACCESS_KEY`, `MODEL_ID`, `FALLBACK_MODEL_ID` from environment variables.
- Try the primary model; on any error or invalid JSON, retry once with the fallback model.
- Strip ```` ```json ```` fences and extract the outermost `{...}` before parsing.
- Validate the parsed JSON with Pydantic; fill missing lists with `[]` and clamp score to 0–100.
- Temperature ~0.2; max output tokens ~3,000.
- All routes live under an `/api` router so they match the App Platform route.
- Local dev only: allow CORS from `http://localhost:5173` (harmless in production).

## 12. AI / LLM design

**Provider:** DigitalOcean Serverless Inference (OpenAI-compatible), base URL `https://inference.do-ai.run/v1/`.

**Models (open-weight):**
- Primary: `gemma-4-31B-it` — 256K context window, enough for full notes.
- Fallback: `openai-gpt-oss-120b`.
- Always confirm exact IDs by calling `/v1/models` with your key.

**Review system prompt (content to put in `prompts.py`):**

> You are Recap Buddy, a patient expert listener. A student is TEACHING you a topic out loud to check their own understanding. Their words come from speech-to-text, so IGNORE grammar, filler words, repetition and transcription errors. Judge ONLY the concepts.
> If REFERENCE MATERIAL is provided, treat it as the primary source of truth and judge coverage against it. If not, use well-established textbook-level knowledge of the topic.
> Sort what the student said into: correct, partial (right idea but incomplete/imprecise), wrong (factually incorrect). Then list the most important concepts they missed (max 5).
> Return ONLY valid JSON with keys: topic, score, summary, correct, partial, wrong, missed, next_step — using the shapes in the API spec. Be specific and short. Never invent mistakes the student did not make.

**User message format:** `TOPIC:` …, `REFERENCE MATERIAL:` … (or "(none)"), `STUDENT'S EXPLANATION:` …

**Diary system prompt:**

> You are writing a student's end-of-day learning diary. Given today's reviews as JSON, write a warm, concise Markdown page: a heading with the date, a table (Topic | Score | Biggest gap), then a short section per topic with "Nailed it", "Fix this", "Revise next". End with "Top 3 priorities for tomorrow". Do not invent topics that are not in the data.

**Scoring guidance (in rubric):** accuracy of what was said ≈ 60%, coverage of key concepts ≈ 40%.

## 13. Frontend specification

### Layout
- **Header:** app name, tagline "Teach it. We'll check it.", today's date.
- **Left sidebar:** Today's Sessions (topic + score badge), "Generate Today's Diary" button, "Clear today" link.
- **Main panel:** Step 1 Topic & Notes → Step 2 Teach (mic + transcript) → Step 3 Review card.
- **Diary view:** replaces the main panel, rendered Markdown + Download + Back buttons.
- **Footer:** "Powered by open-weight `<model>` on DigitalOcean · MIT licensed · GitHub link".

### Components and their responsibilities
| Component | Responsibility |
|---|---|
| `TopicForm` | Topic input, validation |
| `ReferenceUpload` | File picker, calls `/api/extract`, shows file name + pages + remove button, error message |
| `VoiceRecorder` | Start/Stop button with recording indicator (pulsing red dot), "voice not supported" notice |
| `TranscriptBox` | Editable textarea, live word count, Clear button |
| `ReviewCard` | Score ring/badge, summary, grounded badge ("Checked against your notes"), 4 `BucketList`s, next step |
| `BucketList` | One coloured section per bucket with items; "None 🎉" when empty |
| `SessionSidebar` | Lists sessions from storage, select/delete |
| `DiaryView` | Calls `/api/report`, renders Markdown, download button |

### `useSpeech` hook behaviour
- Detect `window.SpeechRecognition || window.webkitSpeechRecognition`; expose `supported`.
- Settings: `lang = "en-IN"`, `continuous = true`, `interimResults = true`.
- Keep final text and interim text separately; expose combined transcript.
- Keep a ref "should be listening"; on `onend`, restart if still true (Chrome stops after silence).
- Expose `start()`, `stop()`, `reset()`, `listening`, `error` (e.g. "mic permission denied").

### App state (in `App.jsx`)
`topic`, `reference` ({filename, pages, text} or null), `transcript`, `review`, `loading`, `error`, `sessions` (today's list), `view` ("teach" | "diary"), `health` (model info).

### Storage
- Key per day: `recapbuddy:YYYY-MM-DD` → list of `{id, topic, createdAt, score, review}`.
- Every read/write wrapped in try/catch; app still works if storage is blocked.

### UI states to handle
Idle · Recording · Uploading notes · Reviewing (spinner + "Checking your concepts…") · Review shown · Error (with Retry) · Generating diary · Diary shown.

### Why "Preserve path prefix" matters
App Platform normally strips the route prefix before passing requests to a component. If it's off, a request to `/api/review` arrives at FastAPI as `/review` and returns 404. Either turn **Preserve path prefix ON** (recommended), or remove the `/api` prefix from the FastAPI router.

### Verify the live deployment
1. Open `https://<your-app>/api/health` → should return `status: ok` and the model ID.
2. Open `https://<your-app>/` → React app loads; footer shows the model.
3. Run the full flow: topic → mic (HTTPS is provided, so the mic works) → review → second topic → diary → download.
4. Open the app's **Runtime Logs** (backend) if anything fails.

### Common deployment problems
| Symptom | Cause / fix |
|---|---|
| `/api/...` returns 404 | Preserve path prefix is off, or the router prefix doesn't match |
| Backend health check failing | Run command port ≠ HTTP port; both must be 8080 |
| 502 on review | Wrong model ID or missing `MODEL_ACCESS_KEY` at run time; check runtime logs |
| Frontend build fails | Lockfile missing (`npm ci` needs `package-lock.json` committed) or build error; run `npm run build` locally |
| Page refresh shows 404 | Catch-all document not set to `index.html` |
| Mic doesn't work | Must be Chrome/Edge on HTTPS; allow mic permission |

### Fallback if deployment blocks the demo
Run backend + frontend locally, record a 60–90 second screen video of the full flow, and submit the video link. The public repo + video still meets all requirements; keep fixing the deploy in parallel.

### After judging
Destroy the app (Settings → Destroy) and delete the model access key so nothing bills after the credits expire.

## 18. Demo script (about 90 seconds)

1. **Problem:** "Students learn by teaching, but nobody's there to listen and correct them."
2. **No notes:** topic "Photosynthesis" → speak with one deliberate mistake and one skipped concept → Review → point at ✅ / ❌ / 🕳️ buckets.

## 21. Risks and mitigations

| Risk | Mitigation |
|---|---|
| Model returns broken JSON | Fence stripping + fallback model + normalization |
| Model ID changes | IDs are env vars; confirm via `/v1/models` |
| Voice not supported | Editable textarea always available |
| Scanned PDFs have no text | Clear 422 error; ask user to paste notes |
| Very long notes | Truncate to ~80k chars (Gemma 4 has a 256K context) |
| Deploy issues | Troubleshooting table in section 15; local demo video as backup |
| API key leak | Key only in App Platform encrypted env var and local `.env` (git-ignored) |
